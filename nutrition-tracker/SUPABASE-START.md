# Supabase 연결 순서

## 1. DB 설정 (한 번)
Supabase 프로젝트 왼쪽 메뉴 → SQL Editor → New query.
같은 폴더의 supabase-setup.sql을 메모장으로 열어 전체 복사 → SQL Editor에 붙여넣기 → Run.
Success가 표시되면 완료입니다. 이 SQL은 개인 기록 저장 테이블, 사용자별 접근 정책, 버전 충돌 방지 저장 함수를 만듭니다.

## 2. 이메일 로그인 설정
Authentication → URL Configuration에서 Site URL을 다음으로 설정하고 Save:
https://yegu1023.github.io/health/nutrition-tracker/
Redirect URLs에도 위 주소를 추가합니다.
Authentication → Sign In / Providers (화면에 따라 Providers) → Email을 켭니다.
Confirm email은 켜둡니다. 회원가입 후 이메일 인증을 완료하고 프로그램에서 로그인하세요.
이메일 발송 제한이 걸리면 Authentication → Users → Add user로 본인 이메일을 생성하고 Auto Confirm User를 켜는 방법도 가능합니다. 비밀번호는 직접 설정하고 공유하지 마세요.

## 3. GitHub 업로드
압축을 풀고 nutrition-tracker 폴더 안 파일과 data 폴더를 기존 저장소의 nutrition-tracker 폴더에 덮어 올립니다.
이번에 반드시 필요한 파일: app.js, cloud.js, index.html, food-worker.js, data/ 전체, style.css.
SQL과 설명 파일은 안내용이며 웹에서 자동 실행되지 않습니다.
GitHub Pages 배포가 끝난 후 Ctrl+Shift+R로 새로고침하세요.

## 4. 실제 사용
상단 로그인 → 회원가입 → 인증 이메일 확인 → 프로그램으로 돌아와 로그인.
기존 브라우저 기록이 있다면 상단 '이전 브라우저 기록 가져오기' 클릭.
같은 날짜는 서버 기록을 유지하고 없는 날짜만 가져옵니다. 내 식품·고정 식단·목표도 없는 항목만 추가합니다.
기존 브라우저 기록은 원래 저장 위치에 유지됩니다. 다른 브라우저의 백업은 관리 → 백업 가져오기로 수동 이전할 수 있습니다 (현재 계정 기록 교체 확인이 표시됨).
식단·물·목표·내 식품·고정 식단 변경 후 '서버 저장 완료'를 확인합니다.
휴대폰에서 같은 주소에 접속하고 같은 이메일로 로그인하면 기록을 불러옵니다.

## 저장과 충돌
기기 기록을 먼저 저장하고 변경 후 서버로 전송합니다. 재접속 시 로그인 계정별로 미동기화 기록을 복구합니다.
앱 열기, 화면 복귀, 1분 주기, 동기화 버튼으로 서버 기록을 확인합니다. 실시간 스트리밍 방식은 아닙니다.
서버 저장이 실패하면 기록은 해당 기기에 남습니다. 인터넷 복구 또는 동기화 버튼으로 재시도하세요.
두 기기에서 동시에 변경해 서버 버전이 달라지면 자동 덮어쓰기를 중단합니다.
관리 → 백업 내보내기로 이 기기 기록을 백업한 후 상단 '서버 기록으로 전환'을 사용하세요.
충돌 기록은 기기에도 별도 보관되며 자동 병합하지 않습니다. 백업에는 Supabase 로그인 토큰이 포함되지 않습니다.
기기에 저장 공간이 부족하다는 메시지가 나오면 즉시 JSON 백업을 받으세요.
현재 비밀번호 찾기 UI는 제공하지 않습니다. 필요 시 Supabase Authentication에서 계정을 관리하세요.

## 검증 범위
계산·기존 저장·검색 DB 압축 해제·검색 결과·동기화 요청·서버 버전 충돌 시 덮어쓰기 방지·기기별 대기 기록 보관을 로직 테스트했습니다.
실제 프로젝트 SQL 실행, 실제 이메일 로그인, 두 기기 실사용, 실제 브라우저 렌더링은 사용자 설정 후 확인이 필요합니다.
연결에는 공개용 Publishable key만 사용합니다. Secret/service_role 키는 포함하지 않았습니다.
음식 검색 공공 DB는 정적 파일로 제공하고 개인 기록만 Supabase에 저장합니다.
