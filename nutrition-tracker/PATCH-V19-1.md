# v19.1 당일 코칭 강화 · 운동 펼침 상태 수정

## 적용
- Supabase health-access 서버는 2026-10-22 배포 완료했습니다. Gemini 키·기존 SQL·기록 테이블을 바꾸지 않았습니다.
- 웹: 압축 안 nutrition-tracker 폴더를 기존 GitHub의 같은 폴더에 덮어 적용합니다. 기존 data 폴더나 기록을 삭제하지 않습니다.
- 앱: Seunggu-Health-1.2.1.apk를 기존 앱 위에 설치합니다. 앱을 먼저 삭제하지 마세요. 같은 앱 ID·서명, 버전 코드 4를 유지했습니다.
- 기존 완료 기록의 '다시 분석'을 누르면 새 기준으로 분석합니다. 이전 피드백은 지우지 않고 새 버전의 캐시 키로 구분합니다.

## 요청 사항별 반영
1. 과거 운동이 없어도 당일 완료 본세트의 중량·반복·RIR·개인 목표 RIR로 다음 동일 운동 목표를 생성합니다. 모든 본세트 RIR이 목표보다 높으면 중량 유지와 반복 1회 증가를 제안합니다. 등록된 반복 상한을 넘기거나 중량 증가 단위를 임의로 만들지 않습니다.
2. 과거 기록이 있으면 동일 루틴의 같은 종목·장비를 먼저 비교하고, 없으면 다른 루틴의 같은 종목·장비를 날짜·루틴과 함께 참고합니다. 세트별 중량/반복/RIR 차이를 코드에서 계산합니다. 장비 고유 식별이 없는 기록은 한계를 유지합니다.
3. RIR null은 미입력입니다. 중량을 유지하고 종목에 등록된 반복 범위를 안내합니다. 등록 범위도 없으면 현재 반복~현재+2회를 제안 범위로 표시하고, 목표 RIR 내에서 수행하도록 합니다. 과거 기록 부재를 이유로 모든 제안을 보류하지 않습니다.
4. 당일 목표-기록 섭취량의 양수 차이로 열량·탄수화물·단백질·지방 부족량을 계산합니다. 남은 식사에서 밥·고구마·과일, 계란·두부·생선·살코기, 견과류 등을 활용하는 기존 목표 내 보완 후보를 즉시 만듭니다. 음식별 영양값이 다르므로 임의의 식품 중량을 확정하지 않습니다.
5. 장기 식단/체중 기록이 부족하면 '하루 열량 목표 변경'만 보류합니다. 당일 식사 구성 개선은 생략하지 않으며, 부족량이 있는데 일반적인 '목표 유지'만 반환한 영양 응답은 검증에서 차단합니다.
6. 신뢰도를 운동 수행/영양 섭취/체중 변화로 분리해 코드에서 각각 산정합니다. 당일 수치가 유효한 운동·완료 식단은 과거 체중 없이도 보통 수준이며, 체중 추세만 제한적으로 표시합니다. 부분 식단·잘못된 수치의 한계는 별도로 유지합니다.
7. 기존 카드 안에서 현재 평가 → 실제 수치 근거 → 다음 행동 순서를 사용합니다. 모델 문장과 함께 코드가 계산한 세트·직전 변화·영양 부족량을 표시하며, 운동의 모든 종목별 다음 목표를 전달합니다.
8. Gemini 실제 전송 본문에서 50kg·10회·RIR4 또는 null, 개인 2500kcal 목표, RIR1~3 기준을 확인했습니다. 키는 서버에만 있으며 이름·생년월일·사진·자유 메모는 계속 제외합니다.

## 첫 번째 운동 자동 펼침 원인과 수정
기존 uiWorkoutFocus는 render 때마다 첫 미완료 종목을 찾아 강제로 펼치고 나머지를 접었습니다. 수동 펼침/접기는 화면 DOM에만 반영돼 다음 기록 변경이나 동기화 때 초기화됐습니다.
이제 사용자/날짜/종목 ID별 별도 화면 상태 Map에 펼침 여부를 저장합니다. 첫 방문 때만 첫 미완료 종목을 기본으로 펼치며, 이후 입력·완료 체크·재정렬·동기화 재렌더에서는 수동 상태를 유지합니다. 다른 사람·날짜와 섞이지 않으며 운동 기록이나 DB에 이 화면 상태를 저장하지 않습니다. 앱 완전 재시작 시에는 초기 기본 펼침을 적용합니다.

## API 요청 제한
Gemini 429 응답의 quota/retry 정보를 확인해 분당 요청·토큰 제한과 일일 제한을 구분합니다. 분당 제한이면 최소 60초 또는 서버가 안내한 더 긴 시간 후 재시도하도록 표시합니다. 자동으로 연속 재시도하지 않습니다. Gemini 모델·프로젝트별 한도와 앱 자체 일일 20회 안전 한도는 별개입니다.
앞선 검증 실패를 모두 무료 일일 한도라고 단정할 수 없으며, 이번 검증은 호출 수를 4회로 제한해 모두 성공했습니다.

## 실제 Gemini 결과 (합성 데이터)
### 과거 없음
입력: 케이블 로우 50kg×10회×3본세트, 전 세트 RIR4, 목표 RIR1~3.
출력: "케이블 로우 3세트 모두 50kg, 10회 수행 시 RIR 4로 기록되어 목표 RIR 1~3보다 여유가 있었습니다."
다음 목표: 50kg×11회×3본세트, 목표 RIR1~3.
### 과거 있음
직전 2026-10-15: 50kg×9회×3, RIR2. 오늘 2026-10-22: 50kg×10회×3, RIR4.
출력에서 직전 대비 반복 1회 증가와 현재 RIR을 설명했습니다. 코드 근거에는 중량 변화0kg·반복+1·RIR+2가 들어갑니다.
다음 목표: 50kg×11회×3본세트, 목표 RIR1~3.
### RIR 미입력
입력: 50kg×10회×3, RIR null, 등록 반복 범위8~12.
다음 목표: 현재 50kg 유지, 3본세트, 목표8~12회와 RIR1~3을 안내. 누락 RIR은 추정하지 않습니다.
### 체중 기록 없는 당일 영양
목표2500kcal/탄300g/단150g/지70g, 기록1800kcal/탄180g/단120g/지55g.
계산: 700kcal·탄120g·단30g·지15g 부족.
실제 출력: 밥과 단백질 반찬으로 남은 식사 구성, 계란·두부·생선·살코기로 단백질 보완. 하루 목표 상향은 보류.
전체 응답과 실제 전송 확인 값은 v19-1-live-results.json에 있습니다. 실제 사용자 기록은 쓰지 않았고, 테스트의 DB 읽기·예약·저장은 모의 처리했습니다.
