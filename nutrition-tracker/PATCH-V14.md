# v14 적용 순서 — 식단·운동·건강

이번 버전은 파일 덮어쓰기 외에 Supabase 함수 배포와 SQL 실행이 한 번 필요합니다. 이름과 4자리 비밀번호를 서버에서 확인하고 일반 사용자에게는 본인 기록만 보내기 위한 변경입니다. GitHub와 Supabase에는 아직 자동 적용되지 않았습니다.

## 1. 현재 앱에서 기록 먼저 보관

1. 기존 앱 → 관리 → 동기화. `서버 저장 완료`를 확인합니다. 여러 기기에서 입력했다면 각 기기에서 확인하세요.
2. 관리자 전체 백업 JSON을 내려받아 보관합니다. 자동백업 내보내기가 있으면 함께 보관하세요.
3. 동기화 충돌이나 오류가 있으면 SQL 적용 전에 그 기록부터 확인합니다. 브라우저 사이트 데이터와 저장소는 지우지 마세요.

SQL은 기존 기록·사진을 삭제하거나 초기화하지 않습니다. `nutrition_v14_backup`에 적용 전 서버 기록을 한 번 보관하고, 이후 서버 저장 때마다 직전 상태를 `nutrition_v14_history`에 남깁니다. 기기에는 기존 원본과 최근 운동 변경 60개 보관 기능이 유지됩니다. 처음 관리자 접속 시 기존 기기에 미동기화 기록이 있으면 충돌 상태로 보존해 자동 덮어쓰기를 막습니다. 이것이 과거에 이미 없어진 중량을 복원한다는 뜻은 아닙니다.

## 2. Supabase 함수 먼저 배포

프로젝트: https://supabase.com/dashboard/project/bqinkrveniupnwvdylko/functions

1. 왼쪽 **Edge Functions** → **Deploy a new function** → 편집기로 만드는 항목을 선택합니다.
2. 함수 이름을 **health-access**로 입력합니다. 기존 `analyze-meal`에 붙여넣지 마세요.
3. 기본 예제 코드를 모두 지우고, 압축 안 `supabase/functions/health-access/index.ts` 내용을 전부 붙여넣습니다.
4. 배포하고 함수 설정에서 **Verify JWT / Enforce JWT verification**을 **OFF**로 저장합니다. 이 함수는 앱 자체 세션을 검사합니다.
5. Supabase가 제공하는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 환경변수를 사용합니다. 별도의 OpenAI API 키나 결제 설정은 필요하지 않습니다. 서비스 역할 키를 GitHub나 앱 파일에 넣지 마세요.

CLI를 쓰는 경우 프로젝트 연결 후 `supabase functions deploy health-access --no-verify-jwt`로 배포합니다. 이 버전은 사진 첨부만 사용하며 AI 분석을 호출하지 않습니다. 과거 `analyze-meal` 함수를 남겨 두었다면 사용하지 않는 함수이므로 삭제해도 됩니다.

## 3. Supabase SQL 실행

프로젝트 → **SQL Editor** → **New query**.

1. 압축 안 **supabase-v14-access.sql**을 전부 붙여넣고 **Run**을 누릅니다.
2. 결과의 **administrator_setup_code** 값을 따로 보관합니다. 최초 관리자 설정 때 한 번 씁니다. 공개 GitHub에는 올리지 마세요.
3. SQL이 성공한 뒤에는 이전 버전 앱의 공개 저장이 차단됩니다. 바로 다음 단계의 파일 교체를 진행하세요.

오류가 나면 오류 내용을 확인하고 진행을 멈추세요. 이 SQL은 트랜잭션으로 실행됩니다. 기존 `supabase-v5-shared.sql`이나 `photo-setup.sql`을 다시 실행하면 예전 공개 접근 권한이 생길 수 있으므로 다시 실행하지 마세요. 최초 관리자 설정을 완료한 뒤 재실행하면 설정 코드는 표시되지 않는 것이 정상입니다.

## 4. GitHub 프로그램 파일 교체

압축의 `nutrition-tracker` 폴더 안 다음 10개 파일을 기존 저장소의 **동일한 nutrition-tracker 폴더**에 덮어씁니다.

- index.html
- style.css
- app.js
- protection.js
- access.js (새 파일)
- shared.js
- batch.js
- photos.js
- workout.js
- health.js

기존 food-worker.js 및 음식 데이터 폴더는 그대로 필요합니다. 이 압축은 변경 파일만 담았습니다. `supabase` 폴더와 SQL은 서버 설정용이며 브라우저용 파일 교체만으로 실행되지 않습니다.

GitHub Pages 배포 완료 후 아래 주소를 엽니다.
https://yegu1023.github.io/health/nutrition-tracker/?v=14

예전 화면이 남으면 탭을 닫고 위 주소로 다시 여세요. 기록이 들어 있는 사이트 데이터를 삭제해 캐시를 지우지 마세요.

## 5. 관리자 최초 접속

1. 이름 **조승구**, 본인이 정한 숫자 **4자리 비밀번호**를 입력합니다.
2. **관리자 최초 설정**을 펼치고 SQL 결과의 설정 코드를 입력합니다.
3. **들어가기**를 누릅니다. 기존 조승구 프로필에 관리자 권한을 붙이며, 새 빈 프로필로 교체하지 않습니다.
4. 이후에는 설정 코드 없이 이름·4자리 비밀번호만 입력합니다.

관리자는 모든 사람 탭을 봅니다. 일반 사용자는 본인 기록만 서버에서 받습니다. 다른 사람에게 접속 권한을 주려면 관리자 화면에서 사람을 추가하고, 서버 저장 완료 후 **관리 → 사용자 비밀번호 등록 / 재설정**에서 탭과 동일한 이름과 4자리 비밀번호를 등록합니다. 이미 있는 사람은 새 탭을 만들지 말고 기존 이름으로 비밀번호만 등록하세요. 별도의 회원가입 화면은 없습니다.

비밀번호는 서버에 해시로 저장합니다. 5회 오류 시 해당 이름은 10분 잠깁니다. 세션 최대 기간은 7일이며 브라우저 탭의 세션 저장소를 사용합니다. 관리에서 비밀번호 변경·나가기를 할 수 있고, 미저장 또는 충돌 기록이 있으면 먼저 보관하도록 안내합니다. 기존 기기의 과거 원본·자동백업은 보존하므로 공용 기기의 로컬 데이터까지 숨기는 방식은 아닙니다.

## 반영 내용

- 운동명 입력 즉시 입력창 아래 결과 표시. 한글 조합 입력 대응. 종목 선택 시 부위 자동 선택. 부위를 먼저 고르면 해당 부위만 검색.
- 첨부표 기준 6개 루틴을 `표 기준` 이름으로 별도 제공. 종목 순서·세트 수·목표 횟수 표시. 기존 루틴과 과거 날짜의 운동은 자동 교체하지 않음.
- 새 날짜에서 루틴 불러오기 → `표 기준` 루틴 선택. 기존 중량이 있는 날짜는 빈 루틴으로 덮어쓰지 않음.
- Push A 18 / Pull A 16 / Legs A 17 / Push B 21 / Pull B 20 / Legs B 19 본세트. 준비 세트는 별도 추가.
- 첫 완료 체크 시점의 1분 전을 시작으로 저장. 마지막 종목의 마지막 세트 완료 시점을 종료로 저장. 체크 취소·마지막 세트 추가 시 종료를 다시 기다림. 시작 시점은 유지.
- 자동 운동시간을 `세트 완료 후 자동 휴식` 위에 표시. 시간 수정과 통증·메모 입력 분리. 직접 시간 수정한 날짜는 자동 계산이 덮어쓰지 않음.
- 운동 입력·운동 달력·운동 통계·루틴 관리 메뉴를 스크롤 시 상단 고정.
- 오른쪽 아래 ↑ 맨 위로 이동 버튼.
- 기존 세트 복사·순서 변경·히스토리·종소리·수분 입력·식단·신체정보·사진 첨부 유지. AI 사진 분석 버튼 없음.

## 검증과 적용 후 확인

코드 문법, SQL/PLpgSQL 구문, 식단·운동·건강 회귀 검사, 제공된 기존 백업 보존 검사, 자동 시간·실시간 검색·접속 화면·서버 함수의 모의 요청 검사를 통과했습니다. 실제 사용자 Supabase 배포와 모바일 브라우저 실기 검사는 이 환경에서 수행하지 못했습니다.

적용 후 기존 날짜의 식단·운동·체중과 사진을 먼저 확인하세요. 이후 새 날짜에서 랫풀 검색·부위 선택, 세트 완료 두 번의 시작/종료, 스크롤 고정 메뉴를 확인하고, 일반 사용자 이름으로 본인 탭만 보이는지 확인하세요. 문제가 있으면 전체 백업을 보관한 채 오류 문구를 전달해주세요.
