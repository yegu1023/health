# v19 운동·영양 개인 코칭 업데이트

## 적용 순서
1. 서버: Supabase > Edge Functions > health-access > Code에서 `health-access-v19-dashboard.ts`의 전체 내용을 index.ts에 넣고 Deploy updates 합니다. **2026-10-22 이번 작업에서 새 서버 코드의 배포를 완료했습니다. CEO의 추가 서버 작업은 필요 없습니다.** 위 서버 교체 방법은 향후 재배포용 설명입니다. Gemini 키와 기존 SQL은 그대로 사용합니다. v18 저장 권한 수정도 유지합니다.
2. 웹: ZIP 안 nutrition-tracker 폴더를 기존 GitHub의 같은 폴더에 덮어씁니다. 기존 data 폴더, 기록 JSON, 계정, Supabase 테이블을 삭제하거나 초기화하지 않습니다. ZIP의 서버 TS 파일은 웹 화면에 로드되지 않습니다.
3. 안드로이드: Seunggu-Health-1.2.0.apk를 기존 앱 위에 업데이트 설치합니다. 먼저 삭제하지 마세요. 앱 ID·서명 유지, 버전 코드 3입니다.
4. 관리 > AI 코칭 기준에서 본인의 목표 유형과 RIR 범위를 설정합니다. 유형은 자동으로 근육 증가로 가정하지 않습니다. 칼로리·탄단지 목표는 기존 설정을 사용합니다.
5. 첫 분석 때 확대된 기간의 전송 안내에 다시 동의합니다. 완료한 기록에서 분석하기를 누릅니다. 기존 피드백은 삭제하지 않으며 새 기준에서는 재분석 안내가 표시됩니다.

## 유지한 기능
기존 식단/운동 입력, 달력, 통계, 사용자별 접근, 사진 첨부, 음식 수정, 하루 완료, 스와이프, 동기화 충돌 보호, 백업, 앱 로그인 보관·휴식 알림을 유지합니다. AI가 기존 음식·운동·목표값을 변경하지 않습니다. 기존 캐시/사용량 제한/서버 키 보관을 재사용합니다.

## 평가·계산 변경
- RIR null은 미입력. 개인 범위 우선, 기본 스쿼트·데드 2~3/일반 복합 1~3/고립 1~3.
- 동일 명칭·기록된 장비·동일 루틴의 직전 종목 비교. 중량·횟수가 같을 때 RIR 차이, 본세트·볼륨·순서·선행 세트 차이를 계산합니다. 장비 식별이 없으면 비교 한계를 명시합니다.
- RIR0 반복과 동일 중량의 세트 간 반복 감소를 표시합니다. 1회 RIR0이나 단순 고볼륨을 과훈련으로 판정하지 않습니다.
- 완료 본세트만 직접 근육 하나에 합산하고 간접 자극 노출은 별도 표기합니다. 명칭 규칙은 추정이며 광범위한 기록 분류는 그대로 둡니다. 7/14/28일과 7일 환산을 구분합니다.
- 세션 통증이 있으면 모든 종목의 증량 후보를 막고 통증 유발 여부 확인·중단·무통 대체 검토를 우선합니다. 기존 pain=0은 기본값일 수 있어 통증 없음으로 확정하지 않습니다.
- 7/14/28일 **달력 기간**의 완료 식단만 평균·합계·당시 목표 평균을 계산합니다. 부분 기록/미기록 날짜는 분모에서 제외하고 수를 공개합니다. 평일/주말 및 운동/명시적 휴식일도 분리합니다.
- 체중은 28일 내 앞/뒤 14일 평균을 비교합니다. 각 구간 3회 이상, 최초~최종 14일 이상일 때만 열량 조정의 체중 근거로 사용합니다.
- 근육 증가 목표, 14일 완료 식단 12일 이상, 체중 평균 차이 절댓값 0.2kg 미만, 평균 섭취가 목표 이하이면 100~150kcal 추가 '검토' 후보를 허용합니다. 이 표본·정체 기준은 과도한 단정을 막기 위한 코드상 보수적 기준이며 의학적 판정이 아닙니다. 기존 목표를 자동 변경하지 않습니다.
- 28일 완료 식단 20일 미만이면 장기 영양 결론 보류. 4주 이상 실제 운동 기록이 없으면 장기 수행 결론 보류.
- 단백질 g/kg은 참고 범위만 전달합니다. 개인 목표가 우선이며 근성장·회복·인과관계를 확정하지 않습니다.

## 변경 코드
- `supabase/functions/health-access/analysis.ts`: 읽기 전용 수치 계산, 근육 규칙, 후보 생성, 코칭 원칙, 응답 검증.
- `coach.ts`: 서버의 권한 있는 기록 읽기, 버전별 해시, Gemini JSON 스키마, 근거/후보 참조 검증, 기존 캐시·쿼터·저장 처리.
- `coach-analysis.js`: 같은 계산 모듈의 브라우저용 생성본. 설정/기록 변경 시 캐시 재분석 표시.
- `coach-ui.js`: 기존 카드 출력, 사람별 목표/RIR 설정. 사용자에게 근거는 읽기 쉬운 문구로 표시.
- `enhancements.js`: 기존 기능을 유지하고 새 분석 입력/결과·전송 안내 연결.
- `index.html`, `ui.css`: 파일 로딩과 근거 펼치기 스타일만 추가.
- `build-coach.cjs`: 브라우저 모듈 및 Dashboard 배포용 단일 파일 생성.
- 안드로이드: 같은 웹 모듈 번들, 버전만 1.2.0/3으로 증가. 네이티브 세션/타이머 코드 변경 없음.

## Gemini에 전달되는 데이터
개인 목표 유형·RIR 범위, 적용일별 영양 목표, 키·최근 체중과 28일 체중 추세, 당일 식품명/양/단위/식사 구분/환산 영양값, 완료·부분·미기록 수와 7/14/28일 평균, 운동/휴식일 평균, 완료 본세트 중량/횟수/RIR·순서·선행 노출·세션 통증, 최근 14일 수행 요약, 최대 90일 내 이전 동일 루틴 6회, 정량 근거와 코드가 만든 다음 행동 후보를 보냅니다.
이름·생년월일·사진·자유 메모·계정·키는 보내지 않습니다. 수면·피로·회복·허리·체성분·정확한 식사 시각은 현재 데이터 모델에 없으며 임의로 생성하지 않습니다. 기존 AI 제안은 사용자가 확정한 조정사항이 아니므로 계획으로 재사용하지 않습니다.

## 구조화 응답과 오류 처리
schemaVersion/feedbackType/analysisPeriod/summary/findings/recommendations/confidence/limitations를 Gemini JSON 스키마로 요청합니다. 실제 존재하는 근거 ID와 행동 후보 ID, 날짜·유형·문자열/배열 제한을 검증합니다. 검증 실패는 저장·표시하지 않습니다. 중량·횟수·세트·RIR·열량 범위는 모델이 만든 숫자가 아니라 선택된 코드 후보에서 가져옵니다. 자연어 해석에는 AI의 오류 가능성이 남으므로 근거와 한계를 함께 표시합니다. 새로운 코드 버전 해시로 이전 캐시를 구분하고 과거 결과는 삭제하지 않습니다.

## 출력 예시 (실제 사용자 기록 아님)
합성 기록을 Gemini에 실제 전송해 생성한 예시입니다. 동일 케이블 로우 50kg×10회×3, 직전 RIR2→오늘3 / 개인 목표2500kcal, 14일 평균2100kcal, 28일 전후 체중평균76kg을 사용했습니다.

운동 평가: "근육 증가 목표 대비 식단 열량이 목표치(2500kcal)에 미달(평균 2100kcal)하고 있으며, 체중은 76kg으로 유지 중입니다. 시티드 케이블 로우는 동일 중량에서 RIR이 개선되었습니다."
다음 운동: "시티드 케이블 로우: 50kg × 10회 × 3본세트 · 목표 RIR 1~3" 유지 검토.
식단 평가: "근육 증가 목표 대비 섭취 칼로리가 부족하며 체중은 유지되고 있어 14일 식단과 체중 평균을 근거로 열량 상향 검토가 필요합니다."
식단 조정: "하루 100~150kcal 추가를 검토하세요. 기존 목표를 자동 변경하지 않습니다."
전체 구조화 예시는 `v19-synthetic-examples.json`에 있습니다.

## 추가 개발이 필요한 항목
종목별 통증 위치, 수면/주관적 피로/회복, 허리둘레·체성분 추세, 실제 식사 시간, 머신 고유 식별·덤벨 한쪽/합계 기준, 사용자 확정 코칭 계획 관리가 없습니다. 이 데이터를 가정해 평가하지 않습니다. 종목별 중량 증가 단위와 목표 반복 상한을 신뢰성 있게 설정하기 전까지 자동 증량·자동 계획 변경은 하지 않습니다. 종합/장기 피드백은 기존 운동·식단 카드 안에서 반영하며 별도 화면은 만들지 않았습니다.
