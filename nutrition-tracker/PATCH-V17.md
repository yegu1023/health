# v17 · 입력 중심 UI와 일반 식품 검색

## 적용 방법
1. ZIP을 풀고 `nutrition-tracker` 폴더 안의 파일들을 GitHub의 기존 `nutrition-tracker` 폴더에 같은 이름으로 덮어씁니다.
2. 기존 `data` 폴더는 그대로 둡니다. 이 패치에는 대용량 음식 데이터가 포함되지 않습니다.
3. GitHub Pages 배포 완료 후 새로고침합니다. 화면이 그대로라면 앱을 닫았다 다시 열어주세요.

Supabase SQL 실행·설정 변경은 필요 없습니다. 브라우저 데이터 삭제나 백업 가져오기도 필요하지 않습니다.

## 변경 내용
- 오늘: 영양 요약, 식사 네 줄, 운동 이어하기, 물 +100ml, 체중 입력.
- 끼니 이름을 누르면 음식·섭취량 수정·삭제와 사진 첨부/촬영이 펼쳐집니다.
- 끼니 오른쪽 +: 최근/즐겨찾기/일반 식품/제품/내 식품을 한 창에서 검색.
- 음식의 양 입력 후 +로 여러 개 선택하고 아래의 ‘N개 음식 추가’로 한 번 저장.
- 선택 요약을 펼치면 선택한 음식의 양 수정·빼기가 가능합니다.
- 일반 식품은 비가공 식품과 음식, 제품은 가공식품으로 데이터 분류를 사용합니다. 조리 상태·제조사·기준량을 확인하세요.
- 검색 결과 전체에서 관련도를 평가하므로 바나나·고구마 기본 식품이 제품에 묻히지 않도록 개선.
- 식단 도구에서 텍스트 등록·어제 복사·템플릿·기록 완료 사용.
- 수분의 ‘직접 입력 · 음료’에서 커피/차/게토레이 및 섭취 내역 이용.
- 운동: 진행할 종목의 세트를 펼치고 완료 버튼·휴식 타이머 강조. 접힌 종목은 ‘세트 펼치기 / 접기’로 확인.
- 기존 세트별 완료 체크·준비/본세트·RIR·순서·수정·히스토리·루틴 관리 유지.
- 같은 탭에서 새로고침할 때 진행 중인 운동이 있으면 운동 화면 복귀.
- 하단 오늘/운동/기록/통계/관리 고정. 신체정보는 오늘 체중 또는 관리에서 접근.

## 기록 보존
화면 렌더링은 기록을 초기화하거나 변환하지 않습니다. 기존 동기화 및 계정 코드는 유지합니다.
새 음식 저장은 현재 식사에 추가하며, 저장 실패 시 원본과 선택 목록을 유지합니다.
개인 기록이나 백업 파일은 패치에 포함하지 않습니다.

## 검증
Node 기반 화면/저장/검색 테스트 및 기존 동기화·다중 식품·운동·휴식·건강·텍스트 등록 테스트 통과.
실제 휴대폰 브라우저 시각 검사와 운영 서버 동기화는 이 환경에서 실행하지 않았습니다.
