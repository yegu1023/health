# v7 식사 사진 · AI 초안 패치

v5/v6 프로그램용입니다. 이전 v6 수정도 포함합니다. GitHub Pages에서 직접 운영하는 구조를 유지합니다.

## A. 사진 첨부를 먼저 켜기
1. 기존 프로그램 관리 → 전체 백업.
2. Supabase → SQL Editor → New query → photo-setup.sql 전체 붙여넣기 → Run.
   v5 공유 기록 설정이 아직 안 되어 있다면 supabase-v5-shared.sql도 먼저 실행합니다.
   photo-setup.sql은 비공개 meal-photos 버킷과 공유 보드용 업로드/조회 정책, AI 일일 한도 테이블을 생성합니다. 기존 식단은 삭제하지 않습니다.
3. 압축 안 nutrition-tracker 폴더의 app.js, batch.js, shared.js, photos.js, index.html, style.css를 저장소의 기존 nutrition-tracker 폴더에 덮어 올립니다.
   기존 data 폴더와 food-worker.js는 유지합니다. 대용량 DB는 이번 ZIP에 없습니다.
4. Pages 배포가 끝나면 Ctrl+Shift+R로 새로고침.
5. 각 끼니 ‘사진 첨부’로 갤러리 선택 또는 ‘촬영’으로 카메라를 엽니다. 기기/브라우저에 따라 카메라 선택 방식이 다를 수 있습니다.
6. 사진 첨부 → 관리의 ‘서버 저장 완료’ 확인 → 다른 기기에서 동기화하여 사진 확인.

## B. AI 분석 켜기 (사진 첨부와 별도)
AI API 사용료가 발생합니다. ChatGPT 채팅에 API 키를 보내거나 GitHub에 올리지 마세요.

1. OpenAI API 프로젝트에서 이미지 입력 가능한 모델의 API 사용 권한과 결제/사용 한도를 설정하고 API 키를 발급합니다.
2. Supabase → Edge Functions → Secrets에 아래를 저장합니다.
   OPENAI_API_KEY : 발급한 OpenAI API 키
   MEAL_AI_ACCESS_TOKEN : 비밀번호 관리자 등으로 생성한 무작위 32자 이상 코드 (24~256자 지원). 코드에 sk- 접두어를 쓰지 마세요.
   MEAL_AI_DAILY_LIMIT : 20 (공동 보드 전체 하루 20회. 1~100으로 변경 가능)
   OPENAI_MEAL_MODEL : gpt-4.1-mini (기본값. 계정에서 사용 가능한 이미지/Structured Outputs 지원 모델로 변경 가능)
   SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY 또는 SUPABASE_SECRET_KEYS는 Supabase가 서버에 주입합니다. 사용자 웹페이지에 넣지 마세요.
3. Edge Functions에서 새 함수를 편집기로 만들고 이름을 정확히 analyze-meal로 설정합니다.
   supabase/functions/analyze-meal/index.ts의 내용을 전체 붙여넣고 배포합니다.
   함수의 Verify JWT 설정은 OFF로 합니다. 이 함수는 대신 x-meal-token 접근코드를 검증하며, 코드가 없거나 다르면 분석하지 않습니다.
   CLI를 쓰는 경우 다운로드 폴더 nutrition-tracker에서:
   supabase functions deploy analyze-meal --project-ref bqinkrveniupnwvdylko --no-verify-jwt
   함께 제공한 supabase/config.toml에도 동일 설정이 있습니다.
4. 프로그램 → 관리 → ‘AI 분석 접근코드 설정’에 2번에서 만든 MEAL_AI_ACCESS_TOKEN만 입력합니다.
   OpenAI API 키를 입력하는 칸이 아닙니다. 접근코드는 기기별로 한 번 설정하며 식단 JSON 백업에는 포함되지 않습니다.
5. 끼니 사진의 ‘AI로 식단 초안’ → 전송·사용료 확인 → 결과 검토 → 선택한 음식 한 번에 저장.

## AI 초안 사용
- 사진을 올리는 것만으로 AI를 호출하지 않습니다. 버튼을 누르고 확인했을 때만 호출합니다.
- 사진은 OpenAI API로 전송되어 분석됩니다. API 요청의 store는 false로 설정했습니다. 이 설정이 외부 제공자의 모든 로그·보관을 없앤다는 의미는 아닙니다.
- 음식명, 예상량(g/ml), 100g/100ml 기준 영양값을 제안합니다. 식품 DB에서 후보를 검색합니다.
- 이름과 단위가 정확히 일치하는 후보가 하나일 때만 DB 영양값을 자동 연결합니다. 자동 연결도 확인 후 저장하세요.
- 후보가 여러 개면 직접 선택합니다. 없으면 AI 추정값이 표시되며 ‘DB에서 다른 음식 검색’ 또는 직접 수정이 가능합니다.
- 조리유·소스·숨은 재료·무게는 사진만으로 정확히 알 수 없습니다. 모든 사진 초안 항목은 추정으로 표시합니다.
- 사진 자체가 식사가 아니면 결과가 없을 수 있습니다. 무게 기준이 없는 사진은 분량 오차가 큽니다.
- 확인 전에는 식단에 입력하지 않습니다. 체크를 해제한 음식은 저장하지 않습니다.
- 분량 변경에 따라 실제 섭취 칼로리·탄단지를 비례 계산합니다.
- 같은 사진을 재분석해 저장하면 그 사진으로 등록된 음식만 교체할지 확인합니다. 다른 음식은 유지합니다.
- AI가 식단에 넣은 커피 등은 수분에 자동 중복 추가하지 않습니다. 필요하면 기존 ‘음료 추가 → 식단에 이미 있는 음료와 연결’을 사용하세요.

## 사진 보관과 백업
- 업로드 전 브라우저에서 긴 변 최대 1440px의 JPEG로 압축합니다. 파일 최대 2MB, 한 끼니 최대 6장입니다. HEIC을 기기가 읽지 못하면 JPEG로 바꿔 첨부하세요.
- 사진은 Supabase Storage, 식단 JSON에는 사진 경로만 보관합니다. 경로를 기반으로 만료되는 조회 URL을 만듭니다.
- 로그인 없는 기존 공동 관리 범위가 사진에도 적용됩니다. 비공개 버킷이라는 이유로 사람별 접근이 분리되지는 않습니다. 공유 프로그램 접속자는 다른 사람의 사진도 조회할 수 있습니다.
- ‘첨부 해제’는 식단에서 사진 연결만 제거합니다. 이미 등록한 음식과 Storage 원본 파일은 유지합니다. 원본 영구 삭제는 Supabase Storage에서 관리자가 별도로 처리합니다.
- 식단 JSON 백업에 사진 파일 자체는 포함되지 않습니다. 장기 보관용 사진은 Supabase Storage에서도 별도 다운로드하세요.
- 사진 첨부 후 서버 저장 충돌이 발생해도 사진 파일은 버킷에 남습니다. 공유 식단 메타데이터를 백업하고 관리에서 기록을 정리하세요.

## 오류 확인
- 사진 첨부 실패: photo-setup.sql, Storage 정책·용량, 네트워크 확인.
- AI 설정 필요: Edge Function 배포와 Secrets 확인.
- 접근코드 오류: 기기 관리 메뉴의 코드와 서버 MEAL_AI_ACCESS_TOKEN 일치 확인.
- 오늘 한도 초과: 한국시간 날짜별 보드 전체 호출 예산입니다. 실패한 AI 요청도 예약된 한도에 포함될 수 있습니다. 임의로 자동 재시도하지 않습니다.
- AI 분석 실패: API 결제·권한·모델 설정·네트워크 확인. 사진과 기존 식단은 유지됩니다.

## 검증 범위
기존 식단 계산·수분·사람별 기록·백업, 사진 메타데이터 호환, 처리 중 사람 전환 시 원래 끼니 보존, AI 결과 검증·분량 계산·중복 교체를 테스트했습니다.
Edge Function은 요청/응답을 모의해 접근코드·출처·경로 제한, 일일 한도 차단, 이미지·Structured Outputs 요청과 오류 처리를 검증했습니다.
실제 브라우저 사진 선택/압축/화면, Supabase 업로드·배포, 실제 OpenAI 이미지 분석은 사용자 서버 설정 전이므로 아직 검증하지 않았습니다. 실제 사진 인식 정확도를 확인했다고 주장하지 않습니다.
아직 운영 웹에는 반영하지 않았습니다.
