# v18 · 음식 수정, 빠른 완료, 좌우 이동, Gemini 코칭

## 웹 적용
압축의 nutrition-tracker 폴더 파일을 기존 GitHub 폴더에 같은 경로로 덮어쓰세요. 기존 data 폴더와 기록은 유지합니다.

## 안드로이드 적용
Seunggu-Health-1.1.0.apk를 기존 앱 위에 업데이트 설치하세요. 앱을 먼저 삭제하지 마세요. 같은 서명과 앱 ID를 유지했습니다.

## 기능
- 등록 음식의 삭제 옆 수정: 해당 날짜의 음식 이름·기준량·섭취량·영양값 수정. 다른 날짜·공공 DB 원본은 변경하지 않습니다.
- 음식 수정 시 하루 완료 상태를 해제합니다. 다시 완료하면 변경된 기록을 분석합니다.
- 오늘 식단 상단 식단 도구 옆 하루 기록 완료 버튼.
- 오늘/운동/기록/통계/관리 좌우 스와이프. 입력칸·버튼·팝업·가로 스크롤에서는 오작동 방지.
- 식단 완료 후 최근 완료 식단 최대 14회와 비교한 식단 피드백.
- 운동 완료 후 같은 루틴의 과거 완료 기록 최대 12회와 비교한 운동 피드백. 같은 루틴 기록이 없으면 겹치는 종목의 기록을 참고합니다.
- 처음 Google 전송 동의가 필요합니다. 이름·생년월일·사진·자유 메모는 분석에 보내지 않습니다. 음식·영양·수행 기록, 통증 점수, 키/체중은 보냅니다.
- Gemini 3.5 Flash-Lite 사용. 동일 내용은 서버 캐시를 재사용합니다. 기본 앱 전체 하루 20회 한도. API 자체 무료 한도 초과 시 중지하며 다른 유료 모델로 자동 전환하지 않습니다.
- Google 프로젝트가 유료 요금제이면 같은 모델도 과금될 수 있습니다. 무료 프로젝트 설정을 유지하세요. 무료 데이터는 Google 서비스 개선에 사용될 수 있습니다.

## Supabase 서버 준비 (필수, 한 번만)
1. SQL Editor에서 supabase-v18-coach.sql 실행. 코칭 캐시/사용량 테이블을 추가하며 기존 기록은 건드리지 않습니다.
2. Edge Functions > Secrets에 GEMINI_API_KEY 등록. API 키를 GitHub나 앱 파일에 넣지 마세요.
3. 선택 환경변수 GEMINI_COACH_MODEL=gemini-3.5-flash-lite, GEMINI_COACH_DAILY_LIMIT=20. 생략해도 기본값 사용.
4. health-access 함수의 코드를 health-access-v18-dashboard.ts 전체 내용으로 교체하고 Deploy updates. Dashboard용은 파일 하나라 import 추가가 필요 없습니다. 기존 로그인/동기화/사진 기능 포함.
5. 기존 health-access의 Verify JWT 설정은 그대로 유지합니다(기존 사용자 세션 방식).
6. 완료 기록에서 동의하고 분석. 식단/운동 화면 맨 아래 피드백 확인.

API 키는 이 패치에 포함하지 않았습니다. 전달된 키로 Gemini 3.5 Flash-Lite의 generateContent 연결 테스트는 성공했습니다.
실제 Supabase 배포/설정 여부는 최종 안내를 확인하세요. API 연결 테스트 성공이 서버 배포 완료를 의미하지는 않습니다.
