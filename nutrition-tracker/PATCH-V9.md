# v9 식단 · 운동 기록 패치

## 업로드 방법
1. 기존 앱의 관리 → 전체 백업을 먼저 받으세요.
2. 압축을 푼 뒤 nutrition-tracker 폴더 안의 아래 7개 파일을 GitHub health 저장소의 기존 nutrition-tracker 폴더에 덮어쓰세요.
   app.js / shared.js / batch.js / photos.js / workout.js / index.html / style.css
3. 기존 data 폴더와 food-worker.js는 그대로 두세요. 폴더 전체를 삭제하지 마세요.
4. GitHub Pages 배포가 끝난 뒤 https://yegu1023.github.io/health/nutrition-tracker/?v=9 로 여세요.
5. 하단에 식단 · 운동 · 기록 · 통계 · 관리의 5개 탭이 보이면 적용된 상태입니다. PC는 Ctrl+Shift+R로 새로고침할 수 있습니다. 브라우저 저장 데이터는 삭제하지 마세요.

기존 공동 관리 Supabase 설정을 그대로 사용합니다. 추가 SQL 실행이나 API 결제가 필요 없습니다. 앱 파일 업로드 후 서버 저장 완료 상태를 확인하세요. 이전 버전을 다른 기기에 열어두셨다면 모두 새로고침하세요.

## 운동 사용 순서
1. 위쪽 사람과 날짜를 선택하고 하단 운동 탭을 누르세요.
2. 루틴 불러오기에서 Push A/B, Pull A/B, Legs A/B 중 선택하세요. 기본 루틴은 시작용 구성으로, 루틴 관리에서 수정·삭제하거나 새로 만들 수 있습니다. 중량은 직접 입력합니다.
3. 종목마다 kg·횟수·RIR을 입력하고 완료를 체크하세요. 맨몸 운동 중량은 0을 입력합니다. 준비 체크 세트는 본세트 집계에서 제외됩니다.
4. 종목·세트를 추가하거나 삭제할 수 있습니다. 이전 기록이 있으면 종목 위에 직전 완료 세트를 표시합니다. 이전 운동 복사는 날짜를 선택해 구성을 가져오며 완료·RIR·시간·메모를 초기화합니다.
5. 시간·통증·메모에서 운동한 분, 통증 0~10, 부위와 컨디션을 적으세요. 운동시간은 직접 기록하는 방식입니다.
6. 운동 완료 버튼으로 마무리하세요. 휴식일도 기록할 수 있습니다. 루틴/이전 운동을 불러오거나 휴식일로 변경할 때 기존 날짜 기록이 있으면 교체를 확인합니다.
7. 운동 달력으로 날짜를 이동하고 운동 통계에서 선택일 기준 최근 28일의 부위별 본세트·수행 기록을 확인하세요. 하단 기록·통계 탭은 기존 식단 전용이며 운동의 달력·통계는 운동 화면 안에 있습니다.

덤벨은 한쪽 또는 합계 중 동일 기준을 계속 사용하세요. 플랭크 등 시간 운동의 초는 메모에 남기세요. 현재 자동 1RM·운동 영상·웨어러블 연동·건강 지표 입력은 포함하지 않습니다.

## 휴식 타이머
60·90·120·180초 선택. 화면에 남은 시간을 표시하고 휴식 종료 시 앱 내 알림을 표시합니다. 지원되는 기기는 진동도 사용합니다. 화면이 꺼지거나 앱이 백그라운드에 있으면 알림이 제한될 수 있습니다. 사람별 기록과 별개인 기기 내 임시 타이머입니다.

## 코칭 AI에게 전달
운동 화면 하단의 운동·식단 코칭 기록 다운로드를 누르면 선택한 사람의 선택일 기준 최근 28일 기록을 TXT로 받습니다. 이 채팅에 파일을 첨부하고 다음 운동 추천이나 식단 피드백을 요청하세요. 완료·미완료 세트, RIR, 통증·메모, 음식과 영양 목표·섭취량이 포함됩니다. 사진 파일은 포함하지 않습니다. 앱 내 유료 AI 호출은 없습니다.

## 기록 보존
운동은 각 사람 데이터의 training 필드에 저장하며 기존 식단·사진과 함께 서버 동기화 및 전체/개인 백업에 포함됩니다. 운동 날짜 삭제는 식단과 사진을 삭제하지 않습니다. 루틴 수정·삭제는 과거 기록을 바꾸지 않습니다. 기존 식단 전용 백업도 가져올 수 있지만 전체 교체이므로 새 운동이 없는 과거 백업을 복원하면 현재 운동 기록도 교체됩니다.

AI 사진 분석 버튼·접근코드 설정은 제거한 상태입니다. 사진 첨부·촬영·보기·첨부 해제만 사용합니다.

## 검증
운동 루틴·세트·준비 세트 집계·이전 기록 복사·프로필 분리·입력값 검증·백업 호환·코칭 내보내기 및 기존 식단/사진 회귀 검사를 통과했습니다. 실제 모바일 브라우저와 실제 서버에 새 패치를 업로드한 후의 동작은 사용자 기기에서 확인해야 합니다.
