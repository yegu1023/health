# 식단 기록 v5 패치

## 설치 (순서대로)
1. 기존 프로그램 관리에서 기록을 JSON 백업합니다.
2. Supabase → SQL Editor → New query → 이 폴더의 supabase-v5-shared.sql 전체를 붙여넣고 Run.
   이번 패치에는 v5 SQL만 실행합니다. 예전 로그인 테이블은 삭제하지 않습니다.
3. 압축 내 nutrition-tracker 폴더 안 파일과 data 폴더를 GitHub 저장소의 기존 nutrition-tracker 폴더에 덮어 올립니다.
4. 배포 완료 후 https://yegu1023.github.io/health/nutrition-tracker/ 에서 Ctrl+Shift+R.
5. 상단에 '조승구' 탭과 '＋ 사람 추가'가 나타나는지 확인합니다. '서버 저장 완료' 또는 '서버 기록 확인 완료'를 확인합니다.
6. 기존 기록이 보이지 않으면 '이전 기록 가져오기'를 사용합니다. 이 기기에 남은 v4 로그인 계정 캐시 또는 이전 브라우저 기록에서 조승구 프로필로 없는 날짜만 가져옵니다. 같은 날짜의 현행 기록은 유지합니다.
7. v4 서버에만 기록이 있고 이 기기에 캐시가 없다면, 기존 v4를 쓰던 기기에서 내보낸 JSON을 조승구 탭의 관리 → 백업 가져오기로 불러옵니다. 예전 서버 기록은 이 패치가 자동 삭제하지 않습니다.

## 이번 변경
- 기본 프로필: 조승구. 사람 추가와 이름 변경 지원.
- 사람 탭을 선택하면 식단·물·목표·내 식품·고정 식단·통계가 해당 사람 기록으로 전환됩니다.
- 로그인/회원가입 화면 제거. 같은 프로그램에 접속하는 사람은 모든 프로필을 보고 수정할 수 있는 공동 관리 방식입니다. URL/공개 API 설정을 아는 사람의 접근을 제한하는 개인 인증은 없습니다.
- 내 식품 등록/수정 창의 공공 DB 검색 버튼으로 선택 → 영양값 자동 입력 → 수정 후 내 식품 저장.
- 음식 추가 창에서 여러 음식을 목록에 담고 각 섭취량을 확인한 후 한 번에 저장. DB 검색·내 식품·직접 입력을 섞어 담을 수 있습니다. 목록에서 빼기와 양 수정 지원.
- 선택 중 취소하면 일일 식단에는 추가하지 않습니다.
- 음식 데이터의 누락 영양값은 보완해야 담거나 등록할 수 있습니다.
- 상단 전체 백업/전체 백업 가져오기: 모든 프로필. 관리의 백업/가져오기: 현재 사람만.

## 서버 저장
- 식품 검색 DB는 정적 파일이며, 개인별 기록만 Supabase의 공동 관리 테이블에 저장합니다.
- 기기 변경 후 같은 URL에 접속하면 같은 사람 탭과 기록을 조회·수정합니다. 마지막 선택한 사람은 기기별로 기억합니다.
- 변경을 기기에 먼저 보관한 뒤 서버에 저장합니다. 서버 저장 실패 시 동기화로 재시도합니다.
- 접속/화면 복귀/1분 주기/동기화 버튼으로 확인합니다. 실시간 스트리밍은 아닙니다.
- 두 기기에서 동시에 수정하면 전체 프로필 묶음의 버전 차이를 감지해 자동 덮어쓰기를 멈춥니다.
- 충돌 시 전체 백업을 먼저 받은 뒤 '서버 기록으로 전환'합니다. 미동기화 전체 기록은 기기에도 별도 보관합니다. 충돌은 자동 병합하지 않습니다.
- 서로 다른 기기의 기록은 자동 병합하지 않으므로, 저장 완료를 확인한 다음 다른 기기에서 동기화하고 입력하세요.

## 확인 범위
프로필 분리, 조승구 기본 이름, 로그인 UI 제거, 여러 음식 임시 보관/일괄 저장/취소 데이터 분리, 사람 변경 시 잘못된 배치 저장 방지, 공유 저장·충돌 시 기록 보존, 기존 계산/백업 검증, 전체 음식 DB 검색을 로직 테스트했습니다.
실제 브라우저 화면·클릭과 Supabase의 v5 SQL 실행/접속은 설치 후 확인이 필요합니다.
