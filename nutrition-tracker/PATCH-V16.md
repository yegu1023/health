# v16 — 휴대폰·PC 동기화 수정

## 구성

- 프로그램 패치 ZIP: 개인 기록이 없는 변경 파일입니다.
- nutrition-recovered-2026-10-19.json: 별도로 전달한 개인 기록 통합본입니다. GitHub에 올리지 않습니다.

통합본은 2026-10-19.json(휴대폰)의 식단·운동·현재 목표와 2026-10-19(1).json(PC)의 박민석 프로필 및 PC에만 있던 날짜를 합쳤습니다. 같은 날짜는 실제 입력값이 있는 휴대폰 백업 기준입니다. 제공된 두 원본은 그대로 보관하세요. 두 파일을 내보낸 이후 추가로 입력했다면 새 전체 백업도 먼저 보관하세요.

## 1. 프로그램 교체

압축을 풀고 아래 6개 파일만 GitHub의 기존 nutrition-tracker 폴더에 업로드하여 Commit changes 합니다.

index.html / style.css / shared.js / access.js / frequent.js / sync.js

sync.js는 새 파일이며, frequent.js는 v15 최근 음식 기능을 포함합니다. 나머지 기존 파일과 음식 DB 폴더는 유지합니다. Supabase SQL 실행·함수 재배포·비밀번호 재등록은 필요하지 않습니다.

## 2. PC에서 한 번 통합

1. 배포 완료 후 https://yegu1023.github.io/health/nutrition-tracker/?v=16 에 접속합니다.
2. 조승구로 접속 → 관리 → 전체 백업 가져오기 → 별도 전달된 nutrition-recovered-2026-10-19.json 선택.
3. 확인을 누르면 현재 기기·서버 원본을 보관하고 통합본을 적용합니다. 서버에만 있는 사람·날짜는 유지합니다. 같은 날짜는 가져온 백업이 우선하므로 백업 이후 입력이 있었다면 내용을 확인한 뒤 진행하세요.
4. 자동 저장 후 상단 이름 탭 아래에 '서버 저장 완료'가 표시되는지 확인합니다. 필요하면 동기화 버튼을 누릅니다.
5. 10월 19일 식단과 박민석 탭을 확인합니다. 이제 '서버 기록으로 전환'을 별도로 누를 필요 없습니다.

## 3. 휴대폰도 한 번 통합

1. PC 저장 완료 후 같은 ?v=16 주소로 기존 브라우저에서 접속합니다. 사이트 데이터는 삭제하지 않습니다.
2. 휴대폰에 옛 미동기화 상태가 남아 있으면 위와 동일하게 관리 → 전체 백업 가져오기에서 같은 통합본을 선택하고 저장 완료를 확인합니다.
3. PC와 휴대폰을 동시에 수정하지 않은 상태에서 기준을 맞추세요. 통합본을 만든 후 새로 입력했다면 새 전체 백업을 먼저 보관해야 합니다.
4. 양쪽에 박민석 탭과 10월 19일 기록이 나타나는지 확인합니다. 이후 시크릿 창에서도 같은 기록을 확인하면 서버 저장 여부를 확인할 수 있습니다.

## 변경 사항

- 서버에서 마지막으로 확인한 기준본을 기기에 함께 보관합니다.
- 저장 직전 최신 서버 기록과 기기 변경을 비교합니다. 다른 날짜·다른 프로필·서로 다른 항목의 변경은 합칩니다.
- 저장 직전 다른 기기가 먼저 저장하면 최신 내용을 다시 읽고 최대 3회 재시도합니다.
- 저장 응답을 기다리는 동안 새로 입력한 내용도 유지합니다.
- 같은 값을 양쪽에서 서로 다르게 바꾼 경우 자동 덮어쓰기를 중단하고 충돌 위치를 표시합니다. 이 경우 전체 백업을 보관하고 충돌 내역을 확인해야 합니다.
- 오래된 버전의 미동기화 기록에 기준본이 없으면 내용을 임의로 선택하지 않습니다. 이번 통합본 가져오기로 처음 한 번 맞춥니다.
- 원본 보관에 실패하면 병합 저장을 중단합니다. 기기와 서버 원본은 기기 저장소에 최근 8회까지 보관합니다.
- 동기화 상태를 이름 탭 바로 아래에 표시합니다. 충돌 상태에서 버튼이 조용히 멈추는 문제를 수정했습니다.
- 사용자 비밀번호 등록 전에 프로필 저장을 시도하고 미저장 상태면 이유를 안내합니다.
- 페이지의 나머지 코드가 로드된 뒤 접속을 복구하도록 바꿨습니다.
- 지난 음식·즐겨찾기·식사 복사, 운동 기록, 사진 첨부 기능은 유지합니다.

## 검증 범위

두 기기의 다른 날짜/프로필 수정 병합, 박민석 탭 전달, 기준본 보관, 같은 항목 충돌 시 양쪽 유지, 저장 경합 재시도, 저장 중 추가 입력 유지, 충돌 상태에서 통합본 가져오기, 서버에만 있는 날짜 보존을 모의 요청으로 검사했습니다. 기존 식단 계산·운동 보호·접속·최근 음식 회귀 검사도 통과했습니다. 실제 GitHub 배포·사용자 Supabase 서버·휴대폰 실기 검증은 아직 수행하지 않았습니다.
