# 식단 기록 v6 소규모 패치

## 적용
1. 기존 프로그램의 관리 → 전체 백업을 먼저 받아둡니다.
2. 압축 내 nutrition-tracker 폴더의 app.js, batch.js, shared.js, index.html, style.css를 GitHub 저장소의 기존 nutrition-tracker 폴더에 덮어 올립니다.
3. 기존 data 폴더와 food-worker.js는 유지합니다. 이번 ZIP에는 대용량 음식 DB가 없으므로 기존 폴더를 지우지 마세요.
4. Pages 배포가 끝나면 Ctrl+Shift+R로 새로고침합니다. 모바일은 페이지를 닫았다 다시 열고 필요시 새로고침합니다. 기록이 있는 사이트 데이터를 삭제할 필요는 없습니다.
5. v5가 설치된 프로그램용 패치입니다. v5 공유 테이블 설정을 완료했다면 SQL 재실행은 필요 없습니다.
6. 관리에서 ‘Supabase 설정 필요 · v5 SQL 파일을 실행해주세요’가 표시되면 함께 넣은 supabase-v5-shared.sql을 Supabase → SQL Editor → New query에 전체 붙여넣고 Run을 누릅니다. 이후 관리 → 동기화를 누르세요.

## 섭취량 비례 계산
- 100g 기준 영양값을 보존하면서 실제 섭취량 30g에 맞춰 칼로리·탄수화물·단백질·지방을 30%로 표시/저장합니다.
- 음식 추가의 내 식품 선택, 검색 식품 확인, 직접 입력, 담은 목록, 오늘 식단의 양 수정에서 미리보기와 합계가 갱신됩니다.
- 검색 식품 확인 창은 ‘실제 섭취량’과 계산된 영양값을 먼저 보여주고, 기준 영양정보는 접어서 표시합니다. 누락값 보완 또는 직접 입력 시 편집 영역이 열립니다.
- 기준값 자체를 바꾸려면 ‘기준 영양정보 편집’을 펼칩니다. 실제 섭취량 변경과 영양 기준량 정의 변경은 별도입니다.

## 한 줄 사람 탭
- 상단은 조승구 · 다른 사람 이름 · ＋만 표시합니다.
- 이름 변경, 서버 저장 상태와 동기화, 전체 백업/가져오기, 이전 기록 가져오기는 관리 화면으로 옮겼습니다.
- 공동 관리 방식과 사람별 기록 분리는 유지됩니다.

## 총 수분
- 물, 커피, 차, 우유, 두유, 기타 음료의 이름과 ml를 기록/수정/삭제할 수 있습니다.
- 총 수분 = 빠른 물 입력 + 모든 음료 ml. 순수 물 = 물로 분류한 기록만 합산합니다.
- 커피/차에 70%, 90% 같은 임의 차감률을 적용하지 않습니다. 실제 흡수량 추정치가 아닌 마신 음료량입니다.
- 기존 물 기록과 기존 목표를 그대로 유지합니다. 목표 명칭만 ‘총 수분’으로 바꿨습니다. 관리에서 원하는 2,000ml 등으로 변경할 수 있습니다.
- 수분 카드의 ‘섭취 내역’을 펼쳐 각 기록을 확인합니다. ‘물 ↶’은 빠른 물 입력만 취소합니다.
- 주간/월간 통계와 평균은 총 수분 기준이며, 평균 순수 물도 별도로 표시합니다.

## 라테·두유 등 칼로리 연결
- ‘수분만 기록’: 음료량만 추가. 칼로리는 자동 추정하지 않습니다.
- ‘내 식품 영양값으로 간식에 함께 기록’: ml 단위로 등록된 내 식품을 선택하면 섭취량에 비례해 칼로리·탄단지를 간식에 추가합니다. 먼저 관리에서 직접 등록하거나 DB 검색으로 내 식품에 등록하세요.
- ‘식단에 이미 있는 음료와 연결’: 오늘 식단의 ml 단위 항목을 선택합니다. 그 식단의 섭취량을 수분에 반영하고 칼로리는 중복 추가하지 않습니다. 동일 식단 항목을 수분에 두 번 연결하면 저장을 막습니다.
- 기존 식단에 연결한 음료의 ml는 식단의 섭취량을 따릅니다. 식단에서 양을 바꾸면 수분 기록도 갱신됩니다.
- 수분 화면에서 함께 만든 칼로리 항목은 음료 삭제 시 같이 삭제합니다. 이미 있던 식단을 연결한 경우 음료를 삭제해도 원래 식단은 유지합니다.
- 식단에서 음료 항목 자체를 삭제하면 수분 기록은 유지됩니다. 마신 음료량도 취소하려면 수분의 섭취 내역에서도 삭제하세요.
- 아이스 음료는 컵 총 용량보다 실제 마신 액체량을 입력합니다. 남긴 얼음은 포함하지 마세요.

## 검증 및 범위
100→30g 영양값과 원본 유지, 입력 미리보기, 일일 합계, 물 1,000ml+커피 500ml, 음료 칼로리 연결/중복 방지/삭제 구분, 기존 물·백업 호환, 사람별 기록 분리·서버 충돌 보존, 음식 DB 검색 로직 검증을 통과했습니다.
실제 브라우저 화면과 Supabase의 SQL 실행/연결은 사용자 설치 후 확인이 필요합니다. 아직 운영 웹에는 반영되지 않았습니다.
모든 기기를 v6로 업데이트해서 새 음료 기록을 동일하게 집계하세요.
